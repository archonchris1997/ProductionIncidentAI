The investigation workflow

IncidentWorkflow is a state machine. It runs one phase at a time and saves a checkpoint after each, so a restarted server resumes where it stopped.

Kill switch: POST /incidents/{id}/stop moves any running phase to Stopped. An unrecoverable agent error moves it to Failed.

Three kinds of information

Live toolsWhat production looks like right now. This is the evidence.
Knowledgesearch_knowledge: runbooks and postmortems, how the team handles this kind of problem.
Memoryrecall_similar_incidents: past incidents. Context only; the report labels it “context, not proof”.

Safety rules

  • Agents only get read-only tools. Write tools are reachable only from ActionExecutor, after approval.
  • Tool risk comes from the app's own registry. Unknown tools count as production-changing.
  • Inputs are validated on the server, so Checkout-API; DROP TABLE is rejected.
  • Contradictions are settled by evidence, never by majority vote.
